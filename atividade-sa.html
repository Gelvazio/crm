Contextualização

Uma equipe comercial controla clientes, produtos e vendas em planilhas e perde pedidos por erros simples. Um deles é a condição de pagamento: alguém cadastra uma condição sem nome ou com zero parcelas, e o pedido sai com a forma de pagar errada. Antes de trocar a planilha por um CRM, o gestor exige que cada parte do sistema nasça com testes automatizados, para que uma alteração futura não quebre o que já funciona (teste de regressão).

O CRM é um projeto Vite com um arquivo JavaScript por assunto. O docente já implementou o cadastro de condição de pagamento em src/condicao-pagamento.js: ele valida os dados (validarCondicao), grava, atualiza, exclui e lista pela API (cadastrarCondicao, atualizarCondicao, excluirCondicao, listarCondicoes) e monta a tela (criarTelaCondicao). A condição escolhida aparece depois no pedido, no campo "Cond.Pagt".

Desafio

Você, como aluno consultor, foi chamado para garantir a qualidade do cadastro de condição de pagamento. Escreva um único arquivo de teste, src/condicao-pagamento.test.js, para o único arquivo de código desta atividade, src/condicao-pagamento.js. Siga o padrão AAA (Arrange, Act, Assert), use o matcher mais específico em cada verificação, cubra os valores-limite e substitua a API por mocks onde for preciso provar como ela foi chamada.

O docente faz o teste junto com a turma, em sala, passo a passo (veja a "Aula guiada" no fim desta página): cada grupo de testes é escrito no quadro, digitado por todos, executado e lido em voz alta antes de seguir.

Regras do projeto: use apenas funções normais (function), sem arrow functions, e { } em todo if; não use async/await — encadeie as promessas com .then() e devolva-as com return. A API chega por parâmetro (injeção de dependência), por isso o teste pode trocá-la por uma API falsa ou por um mock.

Resultados esperados

  • Projeto do CRM rodando (npm run dev) com o menu "Cond. Pagto" funcionando.
  • O arquivo src/condicao-pagamento.test.js, com testes para as cinco funções: validarCondicao, cadastrarCondicao, atualizarCondicao, excluirCondicao e listarCondicoes, mais a tela criarTelaCondicao.
  • No mínimo 12 testes, incluindo os valores-limite de parcelas (0, 1, 1.5, texto e vazio).
  • Print do terminal com npx vitest run src/condicao-pagamento.test.js e todos os testes passando.

0 Preparar o ambiente

Antes de escrever qualquer teste, confirme que o projeto roda. Abra o terminal na pasta crm/ e execute:

npm install
npm test
  • npm install baixa o Vitest, o jsdom e o json-server (só na primeira vez).
  • npm test liga o Vitest em modo observação: ele roda os testes de novo sempre que você salva um arquivo. Para rodar uma vez e sair use npm run test:run.
  • Para testar o condicao-pagamento.js você não precisa ligar o json-server: os testes usam uma API falsa em memória (api-falsa.js).

1 Ler o código que será testado

Um bom teste começa pela leitura do código (visão de caixa branca): é lendo que descobrimos todos os caminhos que precisam de teste. Este é o src/condicao-pagamento.js; cada parte tem uma linha de comentário dizendo o que ela faz:

/** Cadastro de condição de pagamento: validação, acesso à API e tela. */

// Importa o molde de tela de cadastro (formulário + tabela) usado por todos os cadastros.
import { criarTelaCadastro } from './tela.js';

// Nome da coleção no banco (json-server) onde as condições ficam guardadas.
export const COLECAO_CONDICOES = 'condicoes';
// Campos do formulário: o que a pessoa digita ao cadastrar uma condição.
export const CAMPOS_CONDICAO = [
  { nome: 'nome', rotulo: 'Nome', tipo: 'text' },
  { nome: 'parcelas', rotulo: 'Parcelas', tipo: 'number' },
];
// Colunas da tabela: o que a tela mostra de cada condição cadastrada.
const COLUNAS_CONDICAO = [
  { chave: 'id', rotulo: 'ID' },
  { chave: 'nome', rotulo: 'Nome' },
  { chave: 'parcelas', rotulo: 'Parcelas' },
];

/**
 * Confere os dados de uma condição de pagamento.
 * @param {{nome: string, parcelas: number}} condicao - Dados.
 * @returns {string[]} Lista de erros (vazia quando está tudo certo).
 */
export function validarCondicao(condicao) {
  // Começa sem erros; cada regra quebrada acrescenta uma mensagem nesta lista.
  const erros = [];
  // Regra 1: o nome é obrigatório (vazio ou ausente é erro).
  if (!condicao.nome) {
    erros.push('Nome obrigatório');
  }
  // Regra 2: parcelas precisa ser número inteiro e pelo menos 1.
  if (!Number.isInteger(condicao.parcelas) || condicao.parcelas < 1) {
    erros.push('Parcelas deve ser um inteiro maior que zero');
  }
  // Devolve a lista: vazia significa que os dados estão válidos.
  return erros;
}

/**
 * Valida e grava uma condição de pagamento.
 * @param {object} api - API injetada.
 * @param {object} dados - Dados da condição.
 * @returns {Promise<object>} Condição salva, com id (recusa se os dados forem inválidos).
 */
export function cadastrarCondicao(api, dados) {
  // Primeiro confere os dados com a validação.
  const erros = validarCondicao(dados);
  // Se houver erro, recusa a promessa com todas as mensagens juntas e não grava nada.
  if (erros.length > 0) {
    return Promise.reject(new Error(erros.join('; ')));
  }
  // Dados válidos: manda a API criar a condição na coleção e devolve o resultado.
  return api.criar(COLECAO_CONDICOES, dados);
}

/**
 * Valida e atualiza uma condição de pagamento.
 * @param {object} api - API injetada.
 * @param {number} id - Id da condição.
 * @param {object} dados - Novos dados.
 * @returns {Promise<object>} Condição atualizada (recusa se os dados forem inválidos).
 */
export function atualizarCondicao(api, id, dados) {
  // Confere os novos dados com a mesma validação do cadastro.
  const erros = validarCondicao(dados);
  // Se houver erro, recusa a promessa e não altera nada no banco.
  if (erros.length > 0) {
    return Promise.reject(new Error(erros.join('; ')));
  }
  // Dados válidos: manda a API atualizar a condição que tem esse id.
  return api.atualizar(COLECAO_CONDICOES, id, dados);
}

/**
 * @param {object} api - API injetada.
 * @param {number} id - Id da condição a excluir.
 * @returns {Promise<boolean>} true se excluiu.
 */
export function excluirCondicao(api, id) {
  // Pede para a API remover a condição desse id (true se existia, false se não).
  return api.remover(COLECAO_CONDICOES, id);
}

/**
 * @param {object} api - API injetada.
 * @returns {Promise<object[]>} Todas as condições de pagamento.
 */
export function listarCondicoes(api) {
  // Pede para a API devolver todas as condições da coleção.
  return api.listar(COLECAO_CONDICOES);
}

/**
 * Monta a tela de condições de pagamento.
 * @param {object} api - API injetada.
 * @returns {HTMLElement} Seção da tela.
 */
export function criarTelaCondicao(api) {
  // Entrega ao molde de cadastro o que mostrar e a função de cada ação da tela.
  return criarTelaCadastro({
    titulo: 'Condições de Pagamento',
    campos: CAMPOS_CONDICAO,
    colunas: COLUNAS_CONDICAO,
    // Botão Salvar: cadastra a condição digitada.
    aoSalvar: function (dados) {
      return cadastrarCondicao(api, dados);
    },
    // Busca as condições para a tela desenhar a tabela.
    aoListar: function () {
      return listarCondicoes(api);
    },
    // Botão Atualizar: grava as mudanças da condição em edição.
    aoAtualizar: function (id, dados) {
      return atualizarCondicao(api, id, dados);
    },
    // Botão Excluir de uma linha da tabela.
    aoExcluir: function (id) {
      return excluirCondicao(api, id);
    },
  });
}

3 Criar o arquivo e importar as ferramentas

Crie o arquivo src/condicao-pagamento.test.js (mesma pasta e mesmo nome do código, mais .test.js) e comece pelos import:

// 3.1 Ferramentas do Vitest: describe agrupa, it é um caso de teste, expect confere o resultado,
//     beforeEach roda antes de cada teste e vi cria mocks (substitutos controlados).
import { describe, it, expect, beforeEach, vi } from 'vitest';
// 3.2 A API falsa guarda os dados em memória: o teste não precisa do json-server ligado.
import { criarApiFalsa } from './api-falsa.js';
// 3.3 O que vamos testar (o nome do arquivo de teste é o do código + ".test.js").
import {
  atualizarCondicao, cadastrarCondicao, criarTelaCondicao, excluirCondicao, listarCondicoes,
  validarCondicao,
} from './condicao-pagamento.js';

// 3.4 Dado de apoio: uma condição válida que várias vezes serve de ponto de partida.
const CONDICAO_OK = { nome: '30/60 dias', parcelas: 2 };
  • describe agrupa os testes de uma mesma unidade; it é um caso de teste.
  • expect(valor).matcher(esperado) é a conferência (o Assert).
  • vi é a caixa de ferramentas de mocks do Vitest.
  • A API falsa troca o json-server por dados em memória: o teste fica rápido e não depende de rede.

4 Testar uma função simples: validarCondicao (padrão AAA)

Todo teste segue três etapas: Arrange (preparar), Act (agir) e Assert (conferir). Aqui também entram os valores-limite: não basta testar o valor certo, teste os vizinhos errados.

// PASSO 4 — Função simples e síncrona: validarCondicao devolve uma LISTA de erros
// (lista vazia = tudo certo). Aqui entram os valores-limite: teste também os vizinhos errados.
// describe agrupa todos os testes da função validarCondicao.
describe('validarCondicao', function () {
  // Caminho 1: condição válida não gera nenhum erro.
  it('devolve lista vazia para uma condição válida', function () {
    // Arrange (preparar): a condição que vamos avaliar
    const condicao = { nome: 'À vista', parcelas: 1 };

    // Act (agir): chamamos a função exatamente uma vez
    const erros = validarCondicao(condicao);

    // Assert (conferir): toEqual compara o CONTEÚDO de listas e objetos (toBe compararia a referência)
    expect(erros).toEqual([]);
  });

  // Caminho 2: sem nome, só o erro do nome aparece.
  it('exige o nome', function () {
    expect(validarCondicao({ nome: '', parcelas: 1 })).toEqual(['Nome obrigatório']);
  });

  // Caminho 3: nome e parcelas errados ao mesmo tempo geram dois erros.
  it('acumula os dois erros quando nome e parcelas estão errados', function () {
    // toHaveLength confere só o tamanho da lista
    expect(validarCondicao({ nome: '', parcelas: 0 })).toHaveLength(2);
  });

  // Valores-limite: it.each repete o mesmo teste para vários valores (%s vira o valor)
  it.each([0, -1, 1.5, '2', undefined])('recusa parcelas = %s (só inteiro >= 1 vale)', function (parcelas) {
    // toContain confere se UM item está dentro da lista, sem exigir a lista inteira
    expect(validarCondicao({ ...CONDICAO_OK, parcelas })).toContain(
      'Parcelas deve ser um inteiro maior que zero',
    );
  });

  // Mesmos limites, agora com valores que devem ser aceitos.
  it.each([1, 2, 12])('aceita parcelas = %s', function (parcelas) {
    expect(validarCondicao({ ...CONDICAO_OK, parcelas })).toEqual([]);
  });
});
  • Um it para cada caminho da função: válida, sem nome, os dois erros e cada tipo de parcela inválida.
  • toEqual compara o conteúdo de listas e objetos; toBe compararia a referência.
  • toContain confere se um item está na lista, sem exigir a lista toda.
  • it.each([...]) repete o mesmo teste para vários valores e evita copiar e colar.
  • Use o matcher mais específico: toEqual([]) diz mais que toBeFalsy().
  • Cada teste é independente: não depende da ordem nem do resultado de outro.

5 Testar as funções com promessa (sem await)

O banco responde de forma assíncrona (fetch). Como o projeto não usa await, cada teste devolve (return) a promessa encadeada com .then:

// PASSO 5 — Funções com promessa: o banco responde de forma assíncrona (fetch), então cada teste
// DEVOLVE (return) a promessa encadeada com .then. Sem o return o teste termina antes
// do resultado chegar e "passa" sem conferir nada.
// describe agrupa os testes que usam a API falsa (dados em memória).
describe('cadastro de condições (API falsa)', function () {
  let api;

  // beforeEach: um banco novo e vazio antes de CADA teste, para um não depender do outro
  beforeEach(function () {
    api = criarApiFalsa();
  });

  // Cadastrar e depois listar prova que a condição foi mesmo gravada.
  it('cadastra e depois encontra a condição na lista', function () {
    return cadastrarCondicao(api, CONDICAO_OK) // Arrange + Act
      .then(function () {
        return listarCondicoes(api); // Act
      })
      .then(function (lista) {
        // Assert: o banco acrescentou o id sozinho
        expect(lista).toEqual([{ ...CONDICAO_OK, id: 1 }]);
      });
  });

  // Dados inválidos: a promessa é recusada e a lista continua vazia.
  it('recusa dados inválidos e não grava nada', function () {
    const invalida = cadastrarCondicao(api, { nome: '', parcelas: 0 });

    // rejects + toThrow: a promessa deve ser RECUSADA com esta mensagem (sem await)
    return expect(invalida)
      .rejects.toThrow('Nome obrigatório; Parcelas deve ser um inteiro maior que zero')
      .then(function () {
        return listarCondicoes(api);
      })
      .then(function (lista) {
        expect(lista).toHaveLength(0);
      });
  });

  // Atualizar: o resultado traz os novos dados e o mesmo id.
  it('atualiza uma condição existente', function () {
    return cadastrarCondicao(api, CONDICAO_OK)
      .then(function () {
        return atualizarCondicao(api, 1, { nome: 'À vista', parcelas: 1 });
      })
      .then(function (atualizada) {
        expect(atualizada).toEqual({ nome: 'À vista', parcelas: 1, id: 1 });
      });
  });

  // Atualizar com dado inválido é recusado, igual ao cadastro.
  it('recusa atualizar com dados inválidos', function () {
    const invalida = atualizarCondicao(api, 1, { nome: '', parcelas: 1 });

    return expect(invalida).rejects.toThrow('Nome obrigatório');
  });

  // Excluir uma condição que existe devolve true e some da lista.
  it('exclui a condição e devolve true', function () {
    return cadastrarCondicao(api, CONDICAO_OK)
      .then(function () {
        return excluirCondicao(api, 1);
      })
      .then(function (excluiu) {
        expect(excluiu).toBe(true);
        return listarCondicoes(api);
      })
      .then(function (lista) {
        expect(lista).toHaveLength(0);
      });
  });

  // Excluir um id que não existe devolve false.
  it('devolve false ao excluir uma condição que não existe', function () {
    return excluirCondicao(api, 99).then(function (excluiu) {
      expect(excluiu).toBe(false);
    });
  });
});
  • Sem o return o teste termina antes do resultado chegar e passa sem conferir nada (o erro mais comum).
  • beforeEach cria um banco novo antes de cada teste: nenhum teste enxerga os dados do anterior.
  • expect(promessa).rejects.toThrow('mensagem') confere uma recusa.
  • O teste de dados inválidos confere duas coisas: a recusa e que nada foi gravado.

6 Isolar a dependência com mock (vi.fn)

Para provar como a API foi usada, trocamos a API por um mock: uma função falsa que devolve o que o teste manda e registra como foi chamada.

// PASSO 6 — Mock: trocamos a API por um substituto para PROVAR como ela foi usada.
// describe agrupa os testes que conferem as chamadas feitas à API.
describe('cadastro de condições com mock da API', function () {
  // Dados inválidos não podem chegar até a API.
  it('não chama api.criar quando os dados são inválidos', function () {
    // vi.fn() cria uma função falsa que registra todas as chamadas recebidas
    const api = { criar: vi.fn() };

    return cadastrarCondicao(api, { nome: '', parcelas: 1 })
      .catch(function () {})
      .then(function () {
        // not.toHaveBeenCalled: garante que NADA foi gravado
        expect(api.criar).not.toHaveBeenCalled();
      });
  });

  // Dados válidos chegam à API com a coleção e os dados certos.
  it('chama api.criar na coleção "condicoes" com os dados informados', function () {
    // mockResolvedValue(x): a função falsa devolve uma promessa já resolvida com x
    const api = { criar: vi.fn().mockResolvedValue({ id: 1, ...CONDICAO_OK }) };

    return cadastrarCondicao(api, CONDICAO_OK).then(function () {
      // toHaveBeenCalledWith confere os argumentos da chamada
      expect(api.criar).toHaveBeenCalledWith('condicoes', CONDICAO_OK);
    });
  });

  // Atualizar manda coleção, id e novos dados para a API.
  it('chama api.atualizar com a coleção, o id e os novos dados', function () {
    const api = { atualizar: vi.fn().mockResolvedValue({ id: 7, ...CONDICAO_OK }) };

    return atualizarCondicao(api, 7, CONDICAO_OK).then(function () {
      expect(api.atualizar).toHaveBeenCalledWith('condicoes', 7, CONDICAO_OK);
    });
  });

  // Excluir manda a coleção e o id para a API.
  it('chama api.remover com a coleção e o id', function () {
    const api = { remover: vi.fn().mockResolvedValue(true) };

    return excluirCondicao(api, 3).then(function () {
      expect(api.remover).toHaveBeenCalledWith('condicoes', 3);
    });
  });
});
  • vi.fn().mockResolvedValue(x) devolve uma promessa já resolvida com x.
  • not.toHaveBeenCalled() prova que nada foi gravado quando os dados são inválidos.
  • toHaveBeenCalledWith('condicoes', dados) prova que a gravação usou a coleção e os dados certos.
  • As funções recebem a api por parâmetro (injeção de dependência): é isso que torna o mock possível.

7 Testar a tela (DOM) com jsdom

O Vitest roda os testes com o jsdom, um navegador de mentira: dá para criar elementos, procurar com querySelector e disparar eventos sem abrir janela.

// PASSO 7 — Tela (DOM): o Vitest usa o jsdom, um "navegador de mentira" sem abrir janela.
// describe agrupa os testes da tela de condições.
describe('criarTelaCondicao', function () {
  // A tabela deve mostrar a condição que já está no banco.
  it('lista a condição cadastrada na tabela', function () {
    const api = criarApiFalsa({ condicoes: [{ id: 1, ...CONDICAO_OK }] });

    const tela = criarTelaCondicao(api);

    // A tabela é desenhada depois que a lista chega: vi.waitFor repete o expect até passar
    return vi.waitFor(function () {
      const linha = tela.querySelector('tbody').rows[0];
      expect(linha.textContent).toContain('30/60 dias');
    });
  });

  // Salvar sem nome deve mostrar o erro embaixo do formulário.
  it('mostra a mensagem de erro ao salvar sem nome', function () {
    const tela = criarTelaCondicao(criarApiFalsa());
    tela.querySelector('[name="parcelas"]').value = '2';

    // dispatchEvent dispara o envio do formulário, como se a pessoa clicasse em Salvar
    tela.querySelector('form').dispatchEvent(new Event('submit', { cancelable: true }));

    return vi.waitFor(function () {
      expect(tela.querySelector('.mensagem').textContent).toBe('Nome obrigatório');
    });
  });
});
  • A tabela só é desenhada depois que a lista chega; vi.waitFor repete o expect até passar (ou estourar o tempo).
  • dispatchEvent(new Event('submit')) faz o papel do clique em Salvar.

9 Dinâmica: o mutante sobrevivente

Um teste só tem valor se falha quando o código está errado. Em dupla, altere o condicao-pagamento.js e rode os testes:

Mutante (alteração)Quem deve falhar
Trocar condicao.parcelas < 1 por condicao.parcelas <= 1"aceita parcelas = 1" e o teste da condição "À vista"
Apagar !Number.isInteger(condicao.parcelas) ||"recusa parcelas = 1.5" e "recusa parcelas = 2" (texto)
Apagar a linha if (!condicao.nome) da validação"exige o nome"
Remover o return Promise.reject(...) do cadastrarCondicao"recusa dados inválidos e não grava nada" e o mock de criar não chamado
Trocar a coleção condicoes por outro nomeos testes com mock e os de listar

Se nenhum teste falhar, o mutante sobreviveu: escreva o teste que faltava. Depois desfaça a alteração no código.
